> 状态：**已确认并完成**（2026-10-29，示例代码不做编译校验）；M1–M4 全部完成：294/294 文档、审计 0 错误。

> `docs/05-gallery-page-switch-lag.zh.md`、`docs/09-project-restructure-phase1.zh.md`。

## 1. 背景与问题

Gallery 目前是**展示站**，不是文档站：

| 现状 | 证据 |
| --- | --- |
| 294 个目录条目里，只有 166 个有独立条目页（区块 111 + 特殊组件 55） | 源码中 `ArcItemPage` 子类 166 个，全部位于 `Blocks.*` / `Special.*` |
| 128 个组件**没有**自己的页面，只能通过 67 个非条目展示页里的 `h2` 分节命中 | `--audit` 用"标题归一化后出现在某页任意 h2"判定可达，故报 294/294 |
| 文档字段预留但从未使用 | `WhenToUse` / `WhenNotToUse` / `KeyboardAndAccessibility` / `MotionNotes` / `ImplementationNotes` 全仓库 **0 处** override |
| 页面实际内容 = 英文标题 + 一句英文描述 + 演示 + uiarc.dev 外链 | `ArcDocLayout.cs` 固定英文小节 |
| 中文资料只有 25 个组件的复刻对照摘录，不是使用者文档 | `docs/02-component-specs.zh.md` |
| UI 由手写 C# 拼装，未体现组件库自身能力 | `GalleryWindow.cs`：`ArcButton` + 原生 `TextBox` + 手写布局 |

结果：组件没有稳定、可检索、可链接的文档入口；使用者无法回答"它是什么、什么时候用、和别的组件什么关系、为什么选它"；294 条目的完整性只是"能点到"，不是"能读懂"。

## 2. 目标与非目标

### 目标

1. **一个条目一页**：294 个目录条目（128 组件 + 55 特殊组件 + 111 区块）各自拥有独立文档页与稳定 slug。
2. **中文文档**：正文、分类名、界面文案为中文；组件名（API 名）保留英文。
3. **文档回答四个问题**：用途、何时用/不用、与其他组件的关系、与相似组件的区别。
4. **完整性可验证**：每个条目的全部变体/尺寸/状态在预览区现场可用，并由审计比对清单。
5. **实用性可感知**：组件页给出可复制的真实用法代码；区块页本身就是真实页面组合，并列出组成依赖。
6. **Gallery 自身即示范**：导航、搜索、TOC、卡片、代码块、状态徽章等一律用 Arc 自己的组件搭建（dogfooding）。
7. **入口统一**：旧的 67 个非条目展示页（分类合并页与 Foundations/Tokens 等）退役，演示拆入各条目页；不再有"Demo not merged yet"占位。

### 非目标

- 不改组件自身的视觉、交互与实现（除为文档平台必要的公开 API 补充）。
- 不新增第三方 UI/组件/图表/分词库；不联网；不引入 CJK 字体包（按决策"先不处理"）。
- 不做 Web 版、不做在线部署、不做多语言切换（中文优先）。
- 不追求与 uiarc.dev 文档逐字一致：面向**本库使用者**改写，允许说明移植差异。
- 不重写区块内部逻辑，只补文档、预览与依赖关系。

## 4. 文档页规格

固定 8 个区块，顺序不变；每个区块有锚点，右侧 TOC 常驻并滚动高亮。

| # | 区块 | 内容要求 |
| --- | --- | --- |
| 1 | 摘要 | 一句话定义 + 元信息：分类、层级（组件/特殊/区块）、Free/Pro、所属程序集、主控件类型、中文名 |
| 2 | 用途 | 2–4 段：解决什么问题、典型场景、与其他层（令牌/动效）的关系 |
| 3 | 何时使用 / 何时不用 | 两组要点，各 ≥2 条；必须点名替代组件，形成可点击跳转 |
| 4 | 预览 | 完整性预览：全部变体、尺寸、状态（禁用/加载/选中/空态等）；区块页展示完整页面组合 |
| 5 | 与其他组件的关系 | 关系卡片，按类型分组；每条一句话说明"为什么相关"；可点击跳转 |
| 6 | 与相似组件的区别 | 1–3 组对照表，每组 ≥3 个对比维度；维度按组件定制 |
| 7 | 用法示例 | 1–3 个代码片段（XAML 为主、C# 为辅），带说明与一键复制；**不做编译校验**（已确认） |
| 8 | API | 组件/特殊组件：反射生成的属性与事件表（中文说明）；区块：由 `uses` 关系自动生成"组成依赖"表 |
| 9 | 页脚 | 上一个/下一个条目 + uiarc.dev 原文链接 + 一行移植差异说明（如 Pro 独立实现、近似实现） |

语言与口吻：中文技术文档，第二人称"你"；术语统一（受控/非受控、变体 variant、尺寸 size、强调色 accent）；代码与标识符用等宽样式。

## 5. 数据模型

文档内容与预览代码分离：**文字进 JSON，行为进代码**。

- 每个组件项目新增 `Docs/<slug>.json`，作为嵌入资源随项目分发（与"页面随项目走"的现有约定一致）。
- 统一由 `Arc.Avalonia.Demo` 的文档加载器按 slug 读取、校验、缓存。
- slug 以 `arc-catalog.json` 为准，文档缺失即审计失败。

示例（Button）：

```json
{
  "slug": "button",
  "nameZh": "按钮",
  "summary": "触发单一行动的控件：按压缩放、异步时在按钮内显示 loading，标签可就地变化。",
  "purpose": [
    "页面、表单与对话框里最主要的行动入口，同一表面通常只应有一个 primary。",
    "所有状态变化都走弹簧，宽度随标签变化弹性过渡，不打断键盘焦点。"
  ],
  "whenToUse": [
    "任何单次行动，尤其是标签会就地变化（保存 → 已保存）的提交。",
    "短异步操作只需按钮内 spinner 的场景。"
  ],
  "whenNotToUse": [
    "需要按钮自己承担 pending/success 全流程时改用 action-button。",
    "一个主行动带多个备选时改用 split-button。",
    "删除等需要深思的高风险操作改用 hold-to-confirm。"
  ],
  "variants": [
    { "key": "variant-primary", "label": "Primary", "note": "主要行动" },
    { "key": "variant-secondary", "label": "Secondary", "note": "次要行动" },
    { "key": "size-sm", "label": "Small", "note": "紧凑工具栏" },
    { "key": "state-loading", "label": "Loading", "note": "保留焦点、吞掉点击" },
    { "key": "state-disabled", "label": "Disabled", "note": "按变体区分禁用表现" }
  ],
  "relations": [
    { "type": "alternative", "target": "action-button", "note": "按钮自带异步状态时用 action button" },
    { "type": "uses", "target": "spinner", "note": "loading 态内嵌 spinner" }
  ],
  "contrasts": [
    {
      "target": "action-button",
      "title": "Button 与 Action button",
      "rows": [
        { "dimension": "异步反馈", "self": "按钮内 spinner，状态由调用方驱动", "other": "内置 pending → success 状态机" },
        { "dimension": "主要用途", "self": "通用行动入口", "other": "频繁工具栏操作" },
        { "dimension": "失败重试", "self": "由调用方处理", "other": "内置重试态" }
      ]
    }
  ],
  "examples": [
    { "title": "基础用法", "language": "xaml", "code": "<arc:ArcButton Content=\"保存\" Variant=\"Primary\" />" },
    { "title": "异步提交", "language": "csharp", "code": "button.Loading = true; ..." }
  ],
  "api": {
    "type": "ArcButton",
    "exclude": ["TemplatedParent"],
    "descriptions": { "Variant": "视觉层级：Primary / Secondary / Ghost / Danger" }
  }
}
```

### 关系类型（4 种，方向明确）

| type | 含义 | 反向显示 |
| --- | --- | --- |
| `alternative` | 同类二选一，替代关系 | 互补对称：互为"替代" |
| `complement` | 常一起出现，互补关系 | 对称：互为"互补" |
| `uses` | A 包含/依赖 B（页面组合、子控件） | B 页显示"被使用：A" |
| `extends` | A 是 B 的进阶/复杂版本 | B 页显示"基础版：A" |

硬性要求：

- 组件与特殊组件：每个条目 **≥1 条**关系（不含反向），防止孤立节点。
- 区块：每个条目 **≥3 条** `uses`，列出组成组件，同时作为"组成依赖"表的数据源。
- 关系 `target` 必须存在于 catalog；反向关系由渲染层自动生成，JSON 不重复声明。
- 每页 1–3 组 `contrasts`，每组 ≥3 行；`target` 必须存在且必须出现在该页某个 `alternative`/`extends` 关系中（避免"凭空对比"）。

## 6. 预览与完整性

- 每个条目由代码提供一个**完整性预览**：覆盖 JSON `variants` 声明的全部 key，且每个声明状态在预览里**静态可见**（不依赖点击/悬停才出现），因为截图评审与并排比对以静态可见为准。
- 页面代码通过 `ImplementedStates` 暴露已实现的 key 列表；审计逐项比对 JSON 声明，缺一项即失败，多一项即警告。
- 预览优先复用现有演示代码：67 个合并展示页拆分为条目预览；区块/特殊组件沿用现有条目页的 `BuildDemo`。
- 预览区支持明暗与强调色实时切换，切换后状态不丢失。
- 预览控件离开页面时停止动画与定时器（现有 spinner 计时器问题是已知性能债）。

## 7. API 表生成规则

- 组件/特殊组件：从 `api.type` 指定的控件类型反射 **public 可访问的 `AvaloniaProperty` 与 CLR 属性**，以及 public 事件；生成"属性 / 类型 / 默认值 / 说明"四列。
- 默认值取属性默认值；`descriptions` 提供中文说明，未提供时显示"—"（审计对"说明覆盖率"给警告，不阻断）。
- 0 手写属性行：禁止在 JSON 中手工罗列属性清单。
- 区块：没有 `api.type`，渲染"组成依赖"表（来自 `uses` 关系），列为"组件 / 作用说明"。
- 若反射不到任何公开属性，页面显示"该条目无公开 API"，并记录审计警告。

## 9. 技术约束

- 保持现有限制：Avalonia 12 / .NET 10；无新增 NuGet（既无 CJK 字体包也无分词/文档库）；完全离线；单节点构建（`-m:1`）。
- 文档 JSON 随程序集嵌入，运行时零网络请求。
- 页面按需构建 + LRU 缓存（上限约 16 页），离开页面释放预览；不允许 294 页全部驻留。
- 启动只构建外壳 + 首页；搜索索引在首帧后后台构建。
- 中文字体：沿用系统字体回退（Windows 为微软雅黑）；审计输出当前解析到的中文字体名，缺失时给警告；截图中出现缺字/断行问题再补字体。
- 旧页面删除是破坏性变更，安排在 M4、且新页审计全绿之后执行；整个改造在独立分支推进，按里程碑提交。

## 12. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 内容量大（约 15 万字 + 294 页预览拆分） | JSON 模板化 + 按项目并行分工（文件互不重叠）+ 审计机器校验，不靠人眼 |

## 13. 待确认假设（如不同意请指出）

1. **语言边界**：组件名保留英文（Button、Input），分类名、正文、界面文案为中文；页面标题显示为"Button 按钮"。
2. **区块不用 API 表**：区块是页面组合，没有公开 API，第 8 区块改为"组成依赖"表（来自 `uses`）。
