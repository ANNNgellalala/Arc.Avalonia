# Arc for Avalonia

A faithful Avalonia 12 / .NET 10 port of **[Arc UI](https://uiarc.dev)** — the React component and block
library for AI-assisted frontend development. The goal is design fidelity, not API parity: the same OKLCH
token set, eight accents, concentric radii, type scale, motion intent and accessibility rules, expressed
as Avalonia `ControlTheme`s and controls.

The port covers **all 294 entries of Arc's catalog**: 128 components, 55 Special components and 111 blocks.
The gallery is no longer just a showcase: it is a **Chinese documentation platform** built with the
controls it documents. Every entry has its own page with eight fixed sections — summary, purpose, when to
use / when not to use, a completeness preview of every variant and state, component relations, head-to-head
contrasts with similar entries, copy-pasteable examples, and an API table generated by reflection.

```powershell
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll            # browse the docs
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll --page button
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll --audit    # 294/294, 0 errors
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll --smoke    # 323 pages, 0 failures
```

## Install

Arc ships as a set of lockstep `0.9.0-alpha` NuGet packages. Start with the meta package and one line
of XAML:

```powershell
dotnet add package Arc.Avalonia --version 0.9.0-alpha
```

```xml
<Application xmlns="https://github.com/avaloniaui"
             xmlns:arc="using:Arc.Avalonia.Theme">
  <Application.Styles>
    <arc:ArcTheme />   <!-- Fluent baseline + Arc tokens + the 11 component themes -->
  </Application.Styles>
</Application>
```

Then call `ArcThemeManager.Apply(app, ArcColorScheme.Light, ArcAccent.Neutral)` once in
`OnFrameworkInitializationCompleted` (all three `samples/` apps do exactly this).

| Package | Contents | Install when |
| --- | --- | --- |
| `Arc.Avalonia` (meta) | `Arc.Avalonia.Theme` + the 12 component families + `Arc.Avalonia.Markdown` + `Arc.Avalonia.Agent` + `AgentUI` + `LifeToday` | normal application |
| `Arc.Avalonia.All` | `Arc.Avalonia` + 5 Special + 6 Blocks packages | you want every surface |
| `Arc.Avalonia.Theme` | L2.5 aggregate theme (Fluent baseline, tokens, component themes) | you already reference individual component packages |
| `Arc.Avalonia.Foundation` | L1 tokens/palette/icons/motion + the atomic controls | only the design-system primitives |
| `Arc.Avalonia.{Inputs,Actions,Navigation,Overlays,Feedback,DataDisplay,Charts,Pickers,Effects,Content,Media}` | L2 component families | you prefer component-level dependencies |
| `Arc.Avalonia.Markdown` | L2 Markdown family: PuraMarkdown syntax + Arc renderers (`ArcMarkdownView`, `ArcMarkdownDocumentView`, `ArcMarkdownChatView`, `ArcMarkdownCodeBlock`), streaming, highlighter, plugin/fence contracts | you render Markdown, AI answers or agent transcripts |
| `Arc.Avalonia.Agent` | L4 agent top layer: pure presentation runtime (event reducer, workspace/session projection, streaming coalescer, approval/attention/artifact queues) + `ArcAgentSurface` | building an agent UI on your own runtime |
| `Arc.Avalonia.AgentUI`, `Arc.Avalonia.LifeToday` | Agent and life surfaces (UI contracts only) | agent / daily-planning UI |
| `Arc.Avalonia.Special.*`, `Arc.Avalonia.Blocks.*` | L3 composition cases | Special components and page blocks |

Every package depends only on Avalonia's official packages (`Avalonia`, `Avalonia.Themes.Fluent`,
`Avalonia.Fonts.Inter`). `tools/check-package.ps1` unpacks each nupkg and fails the release when any
other dependency or any page/doc/demo asset is found.

### Build the packages locally

`Arc.Avalonia.Markdown` consumes `PuraMarkdown.Syntax` from the sibling PuraMarkdown checkout. The local
feed is configured in `NuGet.config` (`../PuraMarkdown/artifacts/nuget`); produce it once with:

```powershell
dotnet pack ../PuraMarkdown/src/PuraMarkdown.Syntax -c Release -o ../PuraMarkdown/artifacts/nuget
```

Then build the solution:

```powershell
# offline; single-node MSBuild is required on this machine
dotnet pack ArcUI.slnx -c Release -o artifacts -m:1 -nodeReuse:false

pwsh -NoProfile tools/check-package.ps1       # R5: ids, deps, xml, license, demo-free
pwsh -NoProfile tools/check-public-api.ps1    # public API diff against tools/api-baselines
```

The version is defined once (`VersionPrefix`/`VersionSuffix` in `Directory.Build.props`, default
`0.9.0-alpha`) and can be overridden with `-p:Version=...`; package versions are managed centrally in
`Directory.Packages.props`.

## Documentation model

* **One page per catalog entry.** 294 pages, each reachable from the sidebar (23 component categories,
  5 special-component categories, 6 block groups) and via `--page <slug>`.
* **Eight fixed sections** in the same order on every page, so the platform reads like a book:
  summary → purpose → when to use / when not to use → preview → relations → contrasts → examples → API.
* **Relations are authored once** with four types (`alternative`, `complement`, `uses`, `extends`); the
  reverse direction ("被使用", "基础版本") is rendered automatically.
* **Contrasts are structured**: 1–3 similar entries per page, each with at least three custom dimensions.
* **Previews are complete**: every declared variant/state is visible statically, without clicking, so the
  page can be reviewed from a screenshot.
* **API tables are generated**: public properties, events, types and default values are read from the
  control type by reflection; only the Chinese descriptions are hand-written.
* **Documentation is data**: the prose lives in `Docs/<slug>.json`; only the preview lives in code. The
  validator in `Arc.Avalonia.Docs.Abstractions` (namespace `Arc.Avalonia.Demo`) checks required sections, dangling relations, contrast targets, declared
  versus implemented preview states and CJK coverage.

Search covers titles, Chinese names, summaries, body text and relation notes. The status page lists all 294
entries with their remaining defects (none at the moment) and links straight to the page.

## Design tokens

Every token from Arc's `foundation.css` is defined in OKLCH in
[`ArcPalette.cs`](src/Foundation/Arc.Avalonia/Theme/ArcPalette.cs) and converted to sRGB by the small
[`ArcColor.cs`](src/Foundation/Arc.Avalonia/Theme/ArcColor.cs) engine (OKLab maths, CSS `color-mix(in oklab)`).

* Light and dark palettes, neutral plus eight accents (neutral, violet, blue, green, amber, orange, coral,
  rose), accent-tuned control colours.
* Semantic roles only: `ArcBackground`, `ArcSurface`, `ArcSurfaceMuted`, `ArcForeground`, `ArcTextSecondary`,
  `ArcBorder`, `ArcAccent`, `ArcSuccess`, `ArcDanger`, `ArcControlOn`, `ArcSeries1..4`, …
* Radii 18 / 26 / 34 / pill with concentric nesting; control heights 36 / 44 / 50; 4 px spacing grid;
  type scale 12…72 with 400/500 weights; floating-only shadows.
* Motion presets: `SpringSmooth` (0.40 s, no overshoot), `SpringSnappy` (0.26 s), `SpringMorph` (0.42 s),
  plus 120/160/240/480 ms tweens — `ArcSpringEasing` samples a damped oscillator, `ArcThemeManager.ReducedMotion`
  removes travel for reduced-motion branches.
* Lucide icons at stroke 1.75 on the 24 unit grid, embedded in `ArcIconData` (264 names, extensible at runtime through `ArcIcon.Register` / `IArcIconProvider`).

Theming at runtime:

```csharp
ArcThemeManager.Apply(Application.Current!, ArcColorScheme.Dark, ArcAccent.Violet);
```

Every component resolves colours through `DynamicResource`, so a scheme or accent swap restyles the whole
tree without rebuilding it.

## Screenshot harness

Design review happens on rendered PNGs (light and dark), not on a live desktop:

```powershell
pwsh -NoProfile tools/shots.ps1                      # every page, both themes -> shots/light and shots/dark
pwsh -NoProfile tools/shots.ps1 -Page inputs         # one page
pwsh -NoProfile tools/shots.ps1 -Theme dark
```

The harness builds each page in a real (offscreen) window so styles and resources resolve, then renders it
with Skia. Documentation pages are long, so the renderer measures the natural page height and supports
viewport slices:

```powershell
# slice a long document page: offset 1400, max viewport height 1400
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll --shot shots --page button --theme light --offset 1400
# capture the real documentation shell (three columns, outline) with a specific entry
dotnet src/Apps/Arc.Avalonia.Gallery/bin/Debug/net10.0/Arc.Avalonia.Gallery.dll --shot shots --shell --page button
```

The registry currently renders **323 pages** (294 documentation entries, 5 guides, 3 Markdown component pages, the home and status
pages, and 14 agent/life scene pages) at up to 1400 px per slice.

## Notes on fidelity

* **Fonts** — Arc uses Geist for display and Inter for body. Geist is not available offline, so the port
  uses the bundled Inter for both and documents the substitution.
* **Platform primitives** — Radix and Motion have no direct equivalents; menus, popovers, dialogs and
  toasts use Avalonia `Popup`/`Flyout`/overlay surfaces, and springs are reimplemented as sampled damped
  oscillators with the same intent (state changes never overshoot).
* **Documentation** — the docs are Chinese, written for this port rather than copied from uiarc.dev; Pro
  entries are documented from their public descriptions and marked as independent implementations.
  Examples are documentation only and are not compiled.
* **Pro, Special and Blocks** — all 13 Pro components, 55 Special components and 111 blocks are
  implemented independently from their public documentation and visual descriptions. No Pro source was
  fetched or copied; no commercial UI library is used. Special components approximate the original CSS 3D,
  backdrop-filter, WebGL and fluid effects with layered 2D drawing, translucent materials, springs and
  timers; blocks compose the 128 components into working product surfaces with deterministic sample data.
* **Scope** — all 294 catalog entries are covered, each with a Chinese documentation page. The goal is the
  design system and the component/block set, not a 1:1 API clone.
* **Known limitations** — a few Special components are pure illustrations whose phase cannot be set through
  a public API, so their pages document the curated poster frame; some blocks are composed at gallery
  width and pan horizontally inside the documentation column. Legacy English doc fields on the old item
  pages are no longer rendered and are kept only until a later cleanup.

## Dependencies

No commercial or third-party UI/component library is used. The only NuGet packages across the solution are
**Avalonia**, **Avalonia.Desktop**, **Avalonia.Themes.Fluent** and **Avalonia.Fonts.Inter** (all MIT), plus —
confined to `Arc.Avalonia.Markdown` — **PuraMarkdown.Syntax** (MIT) and its **Markdig** parser (BSD-2-Clause),
which supply the Markdown syntax layer while every control, theme and interaction stays Arc code (ADR 0006).
Every control, chart and surface in this repository is our own XAML/C#. Pro components are implemented independently
from Arc's public documentation and visual descriptions, without using or copying Pro source code.

Package versions are centralised in `Directory.Packages.props` (NuGet central package management); the
dependency policy and its gates live in [`tools/deps-policy.json`](tools/deps-policy.json),
[`tools/check-deps.ps1`](tools/check-deps.ps1) and [`tools/check-package.ps1`](tools/check-package.ps1).
Third-party licences and attribution are listed in [`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md).

## API compatibility

Public API baselines live in [`tools/api-baselines/`](tools/api-baselines) — one text file per package,
generated by reflection. `pwsh -NoProfile tools/check-public-api.ps1` fails on any unbaselined change;
`-Update` rewrites the baselines and must be reviewed like source. This is a deliberate M1 substitute for
`Microsoft.CodeAnalysis.PublicApiAnalyzers`, which is not available in the offline package cache; the
baseline covers public types and member signatures but not parameter defaults, nullable annotations or
attributes yet (planned for M2 when the analyzer package can be restored).
